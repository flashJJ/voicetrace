# 04 · 同类赛事对比与参与决策

> 目标：判断 TRAE 好应用大赏赛值不值得投入，以及如何用同一份产品/能力组合参加不同赛事，避免“为比赛而比赛”。  
> 结论：TRAE 好应用大赏赛**条件性推荐**——适合作为 8 天 ship 的强制 deadline 和曝光机会，不适合作为主要收入来源。若目标是奖金，优先关注支付宝「智能体涌现奖」；若目标是 B 端资源，关注火山引擎 Agent 大赛；若目标是融资，关注文心杯/Antler/Delin。

## 1. 评估模型

### 1.1 期望价值公式

```text
期望价值 = 奖金 × 获奖概率
         + 曝光/背书价值
         + 用户/分发价值
         + 学习/作品集价值
         - 时间成本
         - 机会成本
         - 合规/排他/平台锁定风险
```

### 1.2 决策评分卡

权重：资产匹配 20%、8 天可交付 20%、奖金期望 15%、曝光 15%、分发/用户 10%、学习 10%、风险 -10%。每项 1-5 分。

## 2. TRAE 好应用大赏赛：优缺点

### 2.1 优点

| 优点 | 说明 | 对你的价值 |
|---|---|---|
| 门槛低 | 不限技术背景、产品形态；个人可参加 | 不需要组队/公司资质 |
| 奖项多 | 冠亚季 + 5 个专项奖 + 20 个值得一赏 + 造物故事 + 伯乐/认证 | 拿奖概率高于“只有前三名”的比赛 |
| 曝光强 | 字节系渠道、TRAE 官方展示、投资机构/政府/高校资源 | 作品能被更多人看到 |
| 周期短 | 11.10-12.06，报名 11.23 截止 | 适合作为 8 天 ship 的强制 deadline |
| 工具支持 | TRAE Work/IDE、一键部署、社区教程、直播 | 降低开发和部署成本 |
| 真实用户加分 | 已有用户、付费、收入可作为加分证据 | 有产品的人有优势 |
| 社区生态 | TRAE 社区创作者计划、训练营、活动 | 后续可持续获得曝光 |

### 2.2 缺点

| 缺点 | 说明 | 应对 |
|---|---|---|
| 奖金小 | 冠军 1 万，20 个值得一赏仅 500 | 不要把奖金当主要回报 |
| 成熟产品门槛高 | 明确排除 Demo、原型、效果图、空壳模板 | 冻结范围，做完整闭环 |
| 时间紧 | 距报名截止仅 8 天 | 只做一个核心场景，砍掉非必要功能 |
| TRAE 证据负担 | 需 Session ID、截图、任务历史，不能用同类工具替代 | 从第一天留证据 |
| 评审主观 | 没有公开评分表，实际体验+材料共同决定 | 多目标：专项奖+值得一赏+社区曝光 |
| 赛道拥挤 | 学习/生活/内容创作作品极多 | 选行业服务/客户交付，或做窄场景 |
| 叙事权重 | 冠军往往有强故事/强演示 | 准备 3 分钟故事和 1 个记忆点 |
| 排他性风险 | 可能要求未在其他赛事获奖/未公开 | 提交前读细则，避免冲突 |
| 平台锁定 | 核心开发需用 TRAE | 接受再参加；不要同时用竞品做核心开发 |
| 税务 | 奖金为税前 | 提前了解个税/发票 |

### 2.3 适合/不适合

**适合**：

- 你有一个接近成熟的产品，或能在 8 天做出完整小产品；
- 你想要字节系曝光、作品集、社区背书；
- 你愿意用 TRAE 作为主要开发工具；
- 你能接受“拿奖是概率事件”，更看重 ship 和反馈。

**不适合**：

- 你只想靠奖金赚钱；
- 你需要 3 个月以上才能做出完整产品；
- 你的产品必须依赖竞品 AI 编程工具；
- 你不愿意公开作品/做演示；
- 你有排他性合约或公司限制。

## 4. 分层建议

### 4.1 现在（2026-11）

- **主攻 TRAE 好应用大赏赛**：当前产品为“声迹 · 方言故事书”，主赛道游戏娱乐，目标乐在其中奖 + 造物故事奖 + 值得一赏奖。
- **游戏类第二赛场**：中国独立游戏节初赛已于 11.10 截止、indiePlay 已于 7.17 截止，当前无法参加；可关注 2027 年赛程，或先用 TRAE 比赛验证产品。
- 如果产品与支付/生活服务相关，可同时评估支付宝 PAYATHON（12.26 决赛），但注意排他性与平台要求。
- 如果有出海版本，可评估 Google Cloud AI Builder Cup（12.4 决赛），但英文产品和 Google Cloud 适配成本高。
- **不要**同时开三个新项目；选一个主产品，其他比赛用同一产品适配。

### 4.2 下一季度（2026-12 至 2027-Q1）

- **支付宝「智能体涌现奖」**：奖金池最大（1000 万/年），但需要生活服务场景、支付宝生态适配；提前准备下一季度报名。
- **火山引擎 AI Agent 大赛**：如果有 B 端行业方案，提前积累客户案例。
- **Google Cloud AI Builder Cup / 海外 hackathon**：如果有英文产品，持续参加。

### 4.3 2027 年

- **讯飞星火杯**：如果做 AI 应用/语音/教育，提前准备；竞争极大，需要差异化。
- **华为 HarmonyOS 创新赛**：如果决定投入鸿蒙生态，提前 3-6 个月准备。
- **腾讯云黑客松（游戏/云）**：如果有游戏/云产品。
- **GOAI 世界人工智能开源大赛**：如果有开源项目，500 万奖池值得投入。
- **百度文心杯 / Antler / Delin**：如果转向创业/融资，再考虑。

### 4.4 不建议参加

- 需要长期驻场/搬迁的加速器（除非你准备创业）；
- 需要大团队/公司资质的企业赛；
- 纯算法竞赛（除非你是算法背景）；
- 奖金低但排他性强的比赛；
- 与你的产品方向不匹配、只为“凑履历”的比赛。

## 5. 组合策略：一份产品，多次复用

| 产品类型 | 主比赛 | 复用比赛 | 注意事项 |
|---|---|---|---|
| 生活服务智能体 | 支付宝智能体涌现奖 | TRAE 好应用、支付宝 PAYATHON | 支付宝生态适配；TRAE 开发证据 |
| 企业 Agent/行业方案 | 火山引擎 Agent 大赛 | 讯飞星火杯、TRAE 行业服务 | 客户案例、数据合规 |
| 出海 AI 产品 | Google Cloud AI Builder Cup | Product Hunt、海外 hackathon | 英文、支付、隐私政策 |
| 开源项目 | GOAI | GitHub、Product Hunt | License、社区运营 |
| 游戏/互动内容 | TRAE 游戏娱乐（当前） | 中国独立游戏节（2027）、indiePlay（2027）、腾讯云游戏赛道 | 平台锁定、内容审核；中国独立游戏节/indiePlay 2026 已截止 |
| 鸿蒙应用 | 华为 HarmonyOS 创新赛 | TRAE（如支持）、应用市场 | 鸿蒙开发成本 |

**原则**：同一产品可以适配多个比赛，但不要为了每个比赛改产品定位；先有一个真实用户价值，再换包装。

## 6. 注意事项

### 6.1 排他性与原创

- 仔细阅读每个比赛的“原创/未获奖/未公开”条款；TRAE 上一届明确要求“作品不得在其他赛事中获奖，也不得以参赛成品形态在公开平台展示”。
- 如果同一产品参加多个比赛，注意时间顺序：先参加不要求排他的，再参加要求首发的；必要时向主办方书面确认。
- 不要用同一作品在同期比赛中重复领取“参赛奖”，可能违反规则。

### 6.2 平台锁定

- TRAE 要求核心开发使用 TRAE；支付宝要求支付宝生态；华为要求 HarmonyOS；Google 要求 Google Cloud。
- 选一个主平台，其他平台做适配层；不要为了比赛把产品做成“平台专属”。
- 保留可迁移的 core：数据模型、业务逻辑、AI prompt 层，避免被平台绑死。

### 6.3 知识产权

- 公司/客户项目必须取得授权；明确代码、设计、数据、商标的归属。
- 第三方素材（字体、图片、音乐、API）必须有商用授权；开源组件遵守 License。
- AI 生成内容的版权/商用条款因模型而异；保留生成记录和授权说明。
- 比赛提交的材料（截图、视频、文档）也可能被官方展示；提前确认可公开范围。

### 6.4 数据与隐私

- 涉及用户数据，必须有隐私说明、最小化收集、脱敏展示。
- 不要把真实客户数据/个人信息上传到公开演示环境。
- 医疗、法律、金融、教育等敏感领域，避免给出“诊断/建议”式结论，改用“信息整理/风险提示”。

### 6.5 税务与发放

- 奖金通常为税前金额；了解个人所得税、发票、银行卡/对公账户要求。
- 团队奖金分配提前书面约定，避免纠纷。
- 实物奖品可能涉及运费/税费。

### 6.6 时间与账号

- 所有截止时间按北京时间；不要等到最后一小时提交。
- TRAE 要求中国版与社区同一手机号、同一账号，不要中途改昵称（上一届规则）。
- 提前测试公开链接在手机/电脑/无登录状态下的可用性。

### 6.7 评审与预期

- 评审主观，结果不完全可控；不要把所有希望押在一个比赛。
- 冠军往往需要“产品 + 故事 + 演示”三者都强；专项奖更看单点突出。
- 比赛是曝光和反馈渠道，不是商业成功的保证；赛后继续运营才是长期价值。
