## 1. 当前基线

已经具备：

- 25 个互动故事（3-8 幕），三种叙事模式，全部可读可分支可分享
- 164 条资料库素材，其中 14 条为适龄素材，可分页、搜索、筛选、导出
- 真实模型生成 + 8 项自动验收，异常选择自动修复
- 本地录音棚、浏览器自动转写、声音档案、家庭任务包
- 录音联动：首页统计、故事馆进度、AI 工坊素材、结局家庭声音卡
- 双端部署：GitHub Pages 静态站、Trae 服务端实时生成
- 自动化测试：儿童分级、叙事计划、`choices` 修复、家庭任务包、静态产物检查
- 按 IP 与全站的防刷限额、流式生成、超时保护
- 产品说明 PDF、路演稿、演示视频与字幕（已落后于当前功能，待收尾重做）

尚未具备：

- 真实 10 人外部试玩数据
- 真实亲子试用与外部试玩数据（v0.8 仅有脚本自测）
- 适龄儿童故事与真实亲子试用
- 第二种方言
- 跨实例共享的限流

## 2. 报名前（到 2026-11-23）

目标只有一个：让评委打开链接就能验证「这是真的 AI 应用」。

| 优先级 | 事项 | 验收标准 |
|---|---|---|
| P0 | 真实试玩 | 8-10 人，至少 3 人不熟悉粤语；记录完成率、卡点、分享意愿 |
| P0 | 报名材料补齐 | 主站链接、AI 工坊链接、演示视频公开地址、Session ID 全部可点 |
| P1 | 手机 4G 全链路检查 | 首页、故事、地图、资料库、工坊在移动网络下均可打开 |
| P1 | 成本看护 | 每日检查模型用量，确认全站额度未被异常消耗 |
| P2 | 试玩结论回写 | 用真实数据替换 `docs/contest/08` 的模拟报告 |

不在报名前做的事：新增故事、多方言、首页大改版、引入新依赖。

## 3. 评审期（2026-11-24 至 2026-11-29）

目标是稳定，不是加功能。

- 每日巡检 `/studio` 真实生成一次，确认 3 幕与 7 项验收正常
- 监控 429 与 504 的出现频率，异常时优先调额度而不是改代码
- 保留一个可回滚的成功部署记录，出现问题时回滚
- 不再合并大改动，只修影响体验的缺陷

## 4. 路演准备期（2026-11-30 至 2026-12-03）

- 用真实试玩数据更新产品说明与路演稿
- 补录演示视频，把「自定义素材 → 现场生成」剪进主流程
- 准备离线兜底：录屏 + `/demo` 预生成页，防止现场网络或模型异常

## 5. 赛后（2026-12-07 起）

以下为长期方向。v0.3 的实际范围、顺序与排期以 [`02-v0.3-版本迭代计划.md`](02-v0.3-版本迭代计划.md) 为准，本节不重复任务清单。

按「AI 可体验 > 内容增量 > 方言广度」排序，避免平均用力。

### 5.1 第一优先：把 AI 链路做得更可信

| 事项 | 说明 | 验收 |
|---|---|---|
| 生成过程可见 | 前端按节拍展示「正在写第一幕 / 正在校验」，而不是只转圈 | 用户能说出当前进度 |
| 失败可恢复 | 超时后自动重试一次，再失败给出可操作提示 | 不出现只有 504 的白屏 |
| 验收报告可分享 | 把 7 项检查结果做成可导出的卡片 | 可下载或复制 |
| 提示词版本化 | 把 SYSTEM_PROMPT 抽成带版本号的模块，便于对比效果 | 每次改动可追溯 |

### 5.2 第二优先：内容扩容

- 从 9 个故事扩到 15-18 个，优先补未覆盖的地域与主题
- 每个新模式至少 2 个故事，避免「鬼故事只有一条线」
- 资料库从 91 条扩到 120 条，补足待研究篇目
- 新增故事必须通过结构校验：5 幕、6 选择、4 目标、2 结局、0 悬空引用

### 5.3 第三优先：真实声音

- 录制 3-5 段真实长辈讲述，替换当前浏览器语音合成
- 音频放静态资源目录，控制单段体积，使用懒加载
- 取得讲述者书面或录音同意，标注讲述者与录制时间

### 5.4 第四优先：多方言

数据结构已经预留 `dialect` 与 `modes` 字段，但内容未做。启动条件：

- 有能校对的母语者参与
- 至少有 10 条可靠素材
- 不宣称「支持某方言」，只上线经校对的内容

先做潮汕话或客家话中的一种，不同时开两条线。

## 6. 技术债清单

| 债务 | 影响 | 建议处理 |
|---|---|---|
| 限流为进程内计数 | 多实例下额度放大，重启清零 | 接 Redis 或 Upstash 做共享计数 |
| 分享卡字体依赖系统 | 不同设备字形不一致 | 内嵌一份开源中文字体子集 |
| 语音为浏览器合成 | 情绪与方言准确度有限 | 用真实录音逐步替换 |
| 无自动化测试 | 改动靠手工回归 | 先补数据校验脚本，再补关键页面冒烟测试 |
| 提示词与校验规则耦合在路由 | 调整成本高 | 拆为 `lib/prompt.js` 与 `lib/validate.js` |
| 静态站与服务端形态靠环境变量判断 | 容易漏判 | 抽出 `lib/runtime.js` 统一判断并写测试 |

## 7. 风险登记

| 风险 | 影响 | 应对 |
|---|---|---|
| 模型套餐额度耗尽 | 工坊不可用 | 保留 Mock 降级；全站日额度可随时下调 |
| 平台网关策略变化 | 流式生成失效 | 保留非流式降级路径与 `/demo` 预生成 |
| 真实试玩招不到人 | 缺少用户证据 | 降到 5 人并如实标注样本量 |
| 新增内容语言质量下降 | 可信度受损 | 每个故事至少一次母语者通读 |
| 最后一天改坏 | 无法提交 | 报名前一天冻结代码，只做链接与文案检查 |

## 8. 不做什么

- 不做用户登录、家庭协作、云端故事册
- 不做实时语音识别（没有真实录音素材时无法验收）
- 不为「看起来 AI」而增加无实际作用的模型调用
- 不在本轮做多方言的全量翻译与配音
- 不为了数量牺牲校对质量
