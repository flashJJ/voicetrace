# 从一句童谣，到一本可以玩的方言书

> 项目：声迹 · VoiceTrace\
> 关键词：方言保护、互动叙事、内容结构、分享设计

## 一个很具体的场景

很多家庭都有这样一把声音：会唱童谣，会讲旧事，但只在饭桌上响。

你小时候听过，长大后只记得半句。等你想认真录下来，那个声音可能已经不在了。

声迹想做的不是方言词典，也不是翻译工具，而是一本**可以点、可以听、可以玩、可以发给家人的方言故事书**。

## 为什么选择「互动故事」而不是「词典」

方言产品常见三种形态：

| 形态 | 优点 | 问题 |
|---|---|---|
| 词典 / 翻译 | 查找快 | 用完即走，没有情绪 |
| 语音识别 | 工具价值高 | 需要真实语料，冷启动难 |
| 短视频 / 纪录片 | 传播强 | 只能看，不能参与 |

互动故事补的是空白：它让读者在情节里做选择，读完会形成一个「我参与了这段记忆」的感受。这种感受比「我查了一个词」更接近分享动机。

## 一本书的结构

每个故事固定五幕、六个选择、两个结局。结构不是随便定的：

- 五幕足够展开一个完整的小故事，又不至于让人读到一半离开
- 六个选择保证至少两条分支线，读完一屏会有「换一个选法」的冲动
- 两个结局让复读有意义，也让分享卡有差异
- 每幕结尾留一个选择，是互动叙事里最自然的继续信号

一个场景的数据长这样：

```js
{
  id: "moonlight-1",
  act: 1,
  title: "骑楼下的月光",
  textYue: "月光光，照地堂。年卅晚，摘槟榔。阿婆坐喺骑楼底，手摇葵扇，一句一句噉唱。",
  textZh: "月光洒在天井里。年三十晚上，人们摘槟榔。阿婆坐在骑楼下，摇着葵扇，一句一句地唱。",
  audioText: "月光光，照地堂……",
  glossary: [
    { term: "地堂", meaning: "天井、屋前的空地", note: "西关大屋常见的天井，夏天用来乘凉。" }
  ],
  choices: [
    { label: "跟住阿婆唱", next: "moonlight-2a" },
    { label: "问阿婆：点解要摘槟榔？", next: "moonlight-2b" }
  ]
}
```

粤语原文、普通话翻译、方言词注释三件套同时出现，是刻意设计：**让不懂粤语的人也能读懂，让懂粤语的人觉得没有被翻译腔冒犯**。

## 同一批素材，三种讲法

只做「温情怀旧」，受众会很窄。声迹用同一批粤语素材做了三种模式：

- **正经 / 温情**：适合一家人一起听，边界是不煽情、不虚构
- **鬼故事**：夜色、悬疑、留白，结尾用民俗解释，不血腥、不宣扬迷信
- **野史**：说书人口吻，明确标注「据传 / 听讲」，不冒充正史

同一首《月光光》，可以讲成阿婆教唱，也可以讲成半夜骑楼下的另一把声音。素材不变，语气变了，受众就从「对乡土有兴趣的人」扩展到「喜欢悬疑和八卦的年轻人」。

## 结尾要留下一个可以分享的东西

读完故事如果只停在「完」，传播链就断了。

声迹在结局后生成一张 1080×1440 的故事卡：故事标题、一句引文、模式、地区。引文最多三行，超出截断，避免长句把版式撑破。

技术上它是浏览器里的 Canvas：

```js
ctx.fillText(line, 132, 790 + index * 82);
```

不用服务端渲染图片，是因为分享卡应当即时生成、可离线、无额外成本。代价是字体依赖系统，不同设备字形会略有差异。

## 声音地图：让内容有地理

9 个故事如果平铺成列表，看起来像样例集。放到地图上，它们就变成了「广州不同角落的记忆」。

地图还顺手解决了一个真实问题：多个故事坐标重合，后绘制的点会盖住前一个，怎么点都只能打开最后一个。做法是按坐标分组，重合的故事合并成一个节点，点击后出现下拉选择。

## 数据先行，AI 后置

项目一开始就没有走「先做录入后台」的路线。91 条粤语素材全部来自可追溯的公开整理文本，每条标注来源、授权、适合的模式。

这样做的好处是：内容可以被审阅，AI 生成有参照物，演示不依赖某个人的私人录音。

真实录音是加分项，不是前置条件。

## 最后

方言保护容易写成口号。真正让人愿意停下来的，往往不是「它在消失」，而是「这个声音我好像也听过」。

故事是入口，选择是参与，分享卡是出口。

这三件事接起来，一本方言书才不只是资料。
