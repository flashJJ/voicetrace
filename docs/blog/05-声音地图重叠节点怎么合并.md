# 声音地图：9 个故事，坐标重合了怎么办

> 项目：声迹 · VoiceTrace\
> 关键词：前端交互、数据分组、可访问性、移动端

## 问题

声音地图上要放 9 个故事。数据来自故事配置里的示意坐标：

```js
{ slug: "moonlight", mapPoint: { x: 400, y: 300 } }
```

上线后发现，其中 6 个故事的坐标完全相同。地图按数组顺序渲染，后绘制的点盖住前一个，用户点来点去只能打开最后一个故事。

这不是样式问题，是数据问题：示意图没有精确坐标，作者给同一地区的故事填了同一个点。

## 第一反应：把点错开

最直接的想法是加偏移量：第一个不动，第二个往右 20px，第三个往右 40px……

但这样做有两个后果：

- 地图上的位置变成假的，点不再代表真实地点
- 9 个故事还能手动错开，50 个故事就会挤成一条线

放弃。

## 正确做法：按坐标分组

既然是同一地点，就把它当成一个节点。节点上显示「广州 · 6 个故事」，点开再选具体故事。

分组逻辑很轻：

```js
const pinGroups = useMemo(() => {
  const groups = new Map();
  stories.forEach((story) => {
    const point = story.mapPoint || { x: 400, y: 300 };
    const key = `${point.x},${point.y}`;
    if (!groups.has(key)) {
      groups.set(key, { key, x: point.x, y: point.y, stories: [] });
    }
    groups.get(key).stories.push(story);
  });
  return Array.from(groups.values());
}, []);
```

结果：3 个单故事节点 + 1 个六故事合并节点。

## 点击行为分两种

- 单故事节点：直接进入故事页，不增加一次点击
- 合并节点：展开下拉，让用户选

```jsx
const handlePinClick = (group) => {
  if (group.stories.length === 1) {
    router.push(`/stories/${group.stories[0].slug}`);
    return;
  }
  setOpenGroupKey((current) => (current === group.key ? null : group.key));
};
```

不给单故事节点也加下拉，是因为「点一下就能读」比「点两下再选」更符合预期。合并只作为例外处理。

## 下拉菜单怎么定位

地图容器使用 800×620 的坐标系，节点用百分比定位。下拉菜单不能挂在节点内部（会被 `overflow: hidden` 裁掉），所以用绝对定位在地图画布上：

```jsx
<div
  className="map-pin-menu"
  style={{
    left: `${(group.x / 800) * 100}%`,
    top: `${((group.y + 34) / 620) * 100}%`,
  }}
>
```

`+34` 是节点的视觉高度偏移，保证菜单出现在节点下方而不是盖住它。

用百分比而不是像素，是为了在移动端缩放时菜单仍然贴着节点。

## 交互细节

一个下拉菜单至少要考虑四件事：

1. **再次点击节点要能收起**
2. **点击菜单外部要关闭**
3. **按 Escape 要关闭**
4. **屏幕阅读器要知道它展开了**

实现上：

```js
useEffect(() => {
  if (!openGroupKey) return;
  const onKeyDown = (event) => {
    if (event.key === "Escape") setOpenGroupKey(null);
  };
  const onPointerDown = (event) => {
    if (!mapCanvasRef.current?.contains(event.target)) setOpenGroupKey(null);
  };
  document.addEventListener("keydown", onKeyDown);
  document.addEventListener("pointerdown", onPointerDown);
  return () => {
    document.removeEventListener("keydown", onKeyDown);
    document.removeEventListener("pointerdown", onPointerDown);
  };
}, [openGroupKey]);
```

按钮上补：

```jsx
aria-expanded={openGroupKey === group.key}
aria-controls={`map-group-${group.key}`}
```

移动端额外确认：

- 菜单不超出视口左右边界
- 375×667 下能完整显示 6 个选项
- 点击选项后菜单关闭，页面跳转

## 为什么不用第三方地图

真实地图需要经纬度、瓦片服务、API Key。而 9 个故事只需要一个「记忆的地图」意象：骑楼、珠江、西关大屋的位置关系，用一张示意图加坐标就够。

用真实地图反而会暴露一个问题：民间传说的地点本来就是模糊的，标得太精确是一种假精确。

## 收获

- 数据重合时，优先改展示方式，不要改数据去迁就 UI
- 合并节点要保留「直接进入」的快捷路径，否则所有用户都多一次点击
- 下拉菜单的无障碍与外部点击关闭，是最容易被漏掉、也最容易被用户感知的部分
- 如果以后故事扩到 30 个以上，这套分组逻辑可以直接复用，不需要重做

一个小地图，能看出产品对「信息密度」的态度：不是把所有点都摆出来，而是在该合并的时候合并。
