# 04 · 数据模型与内容规范

> 最后更新：2026-11-17

项目里的内容分三层：**互动故事**、**资料库素材**、**黄金样品**。三层各自独立，又通过 `storyId` / `corpusId` 关联。

## 1. 互动故事

存放在 `web/lib/stories.js`、`stories-ghost.js`、`stories-wild-history.js`。

### 1.1 顶层字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `slug` | string | URL 标识，同时用于封面文件名 |
| `mode` | string | `heritage` / `ghost` / `wild_history` |
| `modeLabel` | string | 展示用模式名 |
| `featured` | boolean | 是否出现在首页故事馆 |
| `title` | string | 故事标题 |
| `subtitle` | string | 一句话副标题 |
| `dialect` | string | 方言与地区，如「粤语 · 广州西关」 |
| `type` | string | 内容来源类型，如「公有领域改编」 |
| `duration` | string | 阅读时长估计 |
| `cover` | string | 封面路径，必须用 `cover('slug')` 生成 |
| `quote` | string | 故事馆卡片上的引文 |
| `intro` | string | 阅读器开场白 |
| `scenes` | array | 幕列表，见下 |

### 1.2 场景字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 全局唯一，分支跳转靠它 |
| `act` | number | 第几幕 |
| `title` | string | 幕标题 |
| `textYue` | string | 粤语原文 |
| `textZh` | string | 普通话翻译 |
| `audioText` | string | 朗读文本，可与 `textYue` 略有差异 |
| `glossary` | array | 方言词注释，元素为 `{ term, meaning, note }` |
| `choices` | array | 选项，元素为 `{ label, next }`；结局幕为空数组 |
| `ending` | boolean | 是否结局幕 |
| `endingText` | string | 结局收束句，仅结局幕使用 |

### 1.3 结构约束

每个故事必须满足：

- 5 幕
- 6 个选择
- 4 个唯一目标场景
- 2 个结局
- 0 个悬空 `next` 引用

这组约束是校验脚本的判断依据，新增故事后必须重新校验。三条分支线在页面上表现为不同的结局文案。

### 1.4 三种模式

```js
export const storyModes = [
  { key: "heritage", label: "正经模式", title: "留住把声", description: "温暖、克制，适合一家人一起听。" },
  { key: "ghost", label: "鬼故事模式", title: "半夜唔好乱咁望", description: "夜色、悬疑、民俗解释；不血腥，但会让人背后一凉。" },
  { key: "wild_history", label: "野史模式", title: "听讲当年……", description: "说书人口吻，八卦、俏皮；真假难考，但民间的气是真的。" },
];
```

## 2. 资料库素材

存放在 `web/data/corpus/`，按门类拆成 23 个 JSON 文件，每个文件是一个数组。聚合入口是 `web/lib/corpus.js`。

### 2.1 字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 全局唯一，生成接口的 `corpusId` |
| `type` | string | `nursery_rhyme` / `legend` / `proverb` / `custom` / `riddle` 等 |
| `title` | string | 标题 |
| `subtitle` | string | 副标题，常含地区与主题 |
| `region` | string | 地区 |
| `dialect` | string | 方言片区 |
| `summary` | string | 摘要，用于搜索与 Prompt |
| `text` | string | 原文，可空；为空时标注待补充 |
| `tags` | string[] | 标签 |
| `motifs` | string[] | 意象词，用于实体约束 |
| `glossary` | array | 方言词注释 |
| `source` | array | 来源，元素含 `title` / `url` / `license` |
| `license` | string | 授权状态，目前多为 `traditional-public-domain` |
| `storyPotential` | number | 故事潜力评分 1-5 |
| `difficulty` | number | 改编难度 1-5 |
| `goldenSample` | boolean | 是否有对应黄金样品 |
| `modes` | string[] | 适合的叙事模式 |
| `needsResearch` | boolean | 可选，标记篇目或文本待补充 |

### 2.2 文件拆分

```text
web/data/corpus/
├── meta.json                 分类、模式、地区元信息
├── nursery/                  童谣 6 个文件
├── legends/                  传说 6 个文件
├── proverbs/                 谚语与歇后语 4 个文件
├── customs/                  民俗 4 个文件
├── catalog/                  篇目 1 个文件
├── riddles/                  谜语与绕口令 2 个文件
└── golden/                   黄金样品 4 个文件
```

拆分的目的是让单个文件保持在可人工校对的规模，避免一次改动几百行。

### 2.3 新增素材检查清单

- `id` 不与现有条目重复
- `modes` 至少一个合法值
- `source` 写明可追溯的来源与授权
- `glossary` 只收录原文中真实出现的词
- 不确定的史实、年份、人物标注「相传 / 据传」
- 运行 `npm run build`，确认 JSON 可被正确导入

## 3. 黄金样品

存放在 `web/data/corpus/golden/`，是「什么样的输出算合格」的参考答案。

### 3.1 结构

```json
{
  "id": "golden-moonlight-v1",
  "storyId": "yue-rhyme-moonlight",
  "mode": "heritage",
  "input": { "title": "月光光", "text": "……" },
  "expected": {
    "language": "yue",
    "entities": ["月光", "地堂", "虾仔"],
    "glossary": [{ "term": "地堂", "meaning": "天井、屋前空地" }],
    "scenes": [{ "act": 1, "title": "……", "summary": "……", "choices": ["……"] }],
    "endings": ["……"],
    "translationZh": "……",
    "safetyFlags": []
  },
  "checks": ["json_schema_valid", "scene_count == 3", "..."]
}
```

### 3.2 与生成接口的关系

- `getGoldenSample(corpusId, mode)` 按素材与模式查找参考资料
- 没有配置模型 Key 时，接口直接返回 `expected` 作为 Mock 输出
- 配置 Key 后，真实输出会与 `expected` 对照，跑 7 项验收

7 项验收：

| 检查项 | 判断 |
|---|---|
| `json_schema_valid` | 是否有 scenes / glossary / translationZh |
| `scene_count == 3` | 是否恰好 3 幕 |
| `ending_scene_present` | 第三幕 choices 是否为空 |
| `glossary_terms_present` | 样品要求的方言词是否全部出现 |
| `translation_present` | 是否有普通话翻译 |
| `entities_are_grounded` | 实体是否能在素材原文中找到 |
| `choices_present` | 前两幕是否各有至少 2 个选择 |

新增黄金样品时，保证 `storyId` 指向真实素材，`expected.glossary` 的 `term` 与素材完全一致，否则验收会失败。

## 4. 内容风格规范

- 粤语原文用粤语书面表达，不写成普通话直译。
- 普通话翻译求自然，不逐字硬翻。
- 方言词注释只解释真实出现的词，并给一句文化背景。
- 鬼故事不写血腥、不写低俗、不宣扬迷信；结尾用民俗或传说解释。
- 野史明确使用「据传 / 听讲 / 野史话」；不冒充正史，不诽谤真实人物，不编造具体年份和数字。
- 不确定的内容宁可模糊，也不要编造细节。

## 5. 授权与来源

- 资料库优先使用公有领域或可引用的公开整理文本。
- `source` 保留原始链接，便于复核。
- 真实家庭录音属于个人内容，上传前必须取得讲述者同意。
- 生成内容不用于商业出版，仅作为参赛与演示。
