# 02 · 技术架构

> 最后更新：2026-11-17

## 1. 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 框架 | Next.js 16.4.6（App Router） | 静态导出与服务端部署共用一套代码 |
| UI | React 19 | 全部为函数组件 + Hooks，无状态管理库 |
| 样式 | 单一 `app/globals.css` | 手写 CSS 变量与响应式，无 Tailwind、无 UI 组件库 |
| 内容 | Markdown/JSON 编译进 bundle | 故事与资料库均为本地数据，无数据库 |
| 图像 | 本地 WebP | `public/covers/*.webp`，900px 宽，构建时不依赖外部服务 |
| 语音 | 浏览器 `speechSynthesis` | 作为「听一段」的补充，不是真人录音 |
| 分享卡 | Canvas 2D | 前端绘制并导出 PNG |
| 模型 | 火山方舟 OpenAI 兼容接口 | 默认 `deepseek-v4.1-flash` |
| 部署 | GitHub Pages + Trae FunctionWeb | 静态演示与实时生成双入口 |

没有数据库、没有登录、没有服务端会话。所有用户数据只存在浏览器内。

## 2. 双构建策略

同一个仓库要产出两种形态，由 `STATIC_EXPORT` 环境变量切换：

```js
// web/next.config.mjs
const isStatic = process.env.STATIC_EXPORT === "true";

const nextConfig = {
  env: {
    NEXT_PUBLIC_BASE_PATH: isStatic ? "/voicetrace" : "",
    NEXT_PUBLIC_SITE_URL: isStatic
      ? "https://flashjj.github.io"
      : "http://localhost:3000",
  },
  ...(isStatic
    ? {
        output: "export",
        trailingSlash: true,
        basePath: "/voicetrace",
        assetPrefix: "/voicetrace/",
      }
    : { output: "standalone" }),
};
```

| 形态 | 触发方式 | 产物 | 用途 |
|---|---|---|---|
| 静态导出 | `STATIC_EXPORT=true` + `next build` | `web/out/` | GitHub Pages |
| 服务端构建 | `next build` | `web/.next/standalone/` | Trae 云端 / 本地生产 |

`basePath` 让静态站的资源路径变成 `/voicetrace/covers/*.webp`；服务端形态下为空字符串。所有拼接路径的地方都读 `NEXT_PUBLIC_BASE_PATH`，见 `web/lib/image.js`。

## 3. 渲染与交互分层

```text
服务端构建期
  data/corpus/*.json  ──import──>  lib/corpus.js  ──>  页面 / 数据查询
  lib/stories*.js     ──import──>  lib/stories.js ──>  /stories、/stories/[slug]

浏览器运行期
  StoryReader   分支状态、幕切换、结局判定
  AudioButton   speechSynthesis 朗读当前幕
  ShareCard     Canvas 绘制 1080×1440 故事卡
  CorpusLibrary 搜索 / 筛选 / 每页 12 条分页
  StoryMap      按坐标分组、重叠节点下拉
  Studio        调用 /api/generate-story，流式读取结果
```

故事页使用 `generateStaticParams` 预生成全部 slug；页面本身是静态 HTML，分支切换完全在客户端完成，不产生额外请求。

## 4. AI 生成链路

```text
浏览器 /studio
   │ POST /api/generate-story
   │ { corpusId } 或 { text, mode }
   ▼
路由校验
   ├─ 请求体 ≤ 8 KB
   ├─ mode ∈ { heritage, ghost, wild_history }
   ├─ 自定义文本 10-600 字
   └─ 限流（IP 分钟 / IP 日 / 全站日 / 单 IP 并发）
   ▼
拼装 Prompt
   ├─ SYSTEM_PROMPT：3 幕结构、JSON Schema、事实约束、长度约束
   ├─ 素材：标题、地区、摘要、原文、方言词
   └─ 模式语气：正经 / 鬼故事 / 野史
   ▼
调用模型（OpenAI 兼容）
   ├─ temperature 0.6
   ├─ max_tokens 1500
   ├─ 方舟端点默认 thinking disabled
   └─ 15 秒超时（AbortSignal.timeout）
   ▼
NDJSON 流式返回
   ├─ 每 4 秒一个 {"type":"ping"} 心跳
   ├─ 成功：{"type":"result", ...}
   └─ 失败：{"type":"error", error, hint}
   ▼
前端读取流
   └─ 解析 result，渲染三幕、注释、翻译、7 项验收
```

### 为什么要流式

Trae 平台的网关在 13-18 秒左右会判定请求超时并返回 504。完整生成需要 10-20 秒，普通 JSON 响应会稳定失败。改成 NDJSON 并每 4 秒发心跳后，网关持续收到数据，连接不会被判超时，前端也能读到最终结果。

### 为什么关闭 thinking

`deepseek-v4.1-flash` 是推理模型。实测它会把 1400 个输出 token 全部用在思考上，正文为空，且耗时顶到网关上限。对火山方舟端点默认加 `thinking: { type: "disabled" }`，正文可在 9-19 秒内返回。可用 `LLM_DISABLE_THINKING=false` 重新打开。

## 5. 限流设计

实现在 `web/lib/rate-limit.js`，是进程内固定窗口计数：

| 场景 | 每 IP 每分钟 | 每 IP 每天 | 全站每天 |
|---|---|---|---|
| 有真实 Key | 5 | 30 | 300 |
| Mock 模式 | 20 | 200 | 2000 |

附加约束：

- 同一 IP 同时只允许一个生成请求
- 请求体超过 8 KB 返回 413
- 超限返回 429 并带 `Retry-After`
- 可用 `RATE_LIMIT_PER_MINUTE`、`RATE_LIMIT_PER_DAY`、`RATE_LIMIT_GLOBAL_DAY` 覆盖

已知局限：计数存在进程内存，多实例部署时各实例独立计数，实例上限为 10，最坏情况下实际额度接近标称值的 10 倍，重启清零。它挡得住普通刷接口，挡不住分布式攻击。需要更强保证时应接入 Redis 做共享计数。

## 6. 7 项自动验收

生成结果不会直接展示为「正确」，而是逐项对照黄金样品：

| 检查项 | 判断 |
|---|---|
| `json_schema_valid` | 是否有 scenes / glossary / translationZh |
| `scene_count == 3` | 是否恰好 3 幕 |
| `ending_scene_present` | 第三幕 choices 是否为空 |
| `glossary_terms_present` | 黄金样品要求的方言词是否全部出现且用词一致 |
| `translation_present` | 是否有普通话翻译 |
| `entities_are_grounded` | 实体是否能在素材原文或摘要中找到 |
| `choices_present` | 前两幕是否各有至少 2 个选择 |

## 7. 部署拓扑

```text
GitHub main 分支
   │ push
   ├──> GitHub Actions（Node 22）
   │      npm ci
   │      node scripts/build-static.mjs
   │        └─ 临时把 app/api 移出，STATIC_EXPORT=true 构建
   │      上传 web/out 到 GitHub Pages
   │
   └──> Trae 部署（手动）
          nodejs20 FunctionWeb
          next build → .next/standalone
          build.sh 复制 standalone + static + public 到 dist
          run.sh 以 0.0.0.0:8000 启动 server.js
```

两套部署的分工：

- 静态站负责「不用等、随时能打开」的内容浏览
- 服务端版本负责「真的能生成」的 AI 体验
- 静态站的导航与 `/studio` 页面会把用户引导到服务端版本

## 8. 已知技术约束

- Next.js 16 的 `output: "standalone"` 不会自动包含 `.next/static` 与 `public`，部署脚本必须手动复制。
- 静态导出下 `app/robots.js` 必须声明 `export const dynamic = "force-static"`，否则构建失败。
- CSS 的 `aspect-ratio` 会被 `<img>` 的 HTML `height` 属性压制，需要显式 `height: auto`。
- 服务端运行时文件系统只保证临时目录可写，本项目不写任何运行时文件，因此不受影响。
- 静态站不能调用 `/api/generate-story`，代码用 `NEXT_PUBLIC_BASE_PATH` 判断当前形态。
