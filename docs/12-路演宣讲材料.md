# 12 · VoiceTrace「声迹」路演宣讲材料

> 更新日期：2026-11-16<br>
> 用途：入围路演、作品宣讲、评委答疑、现场演示<br>
> 建议主讲版本：10 页，约 6 分钟；另附 3 分钟压缩流程<br>
> 核心表达：**不是把方言做成一个翻译工具，而是把地方故事变成可以参与、理解和分享的互动书。**

## 1. 使用前必须统一的口径

### 可以明确讲

- 已有 3 种叙事模式、9 个互动故事。
- 已有 91 条粤语素材，按内容子集拆成 23 个分类文件。
- 已有 8 个黄金样品；真实模型 8/8 样品均通过既定 7/7 自动检查。
- `/demo` 保存了三种模式各 1 个真实模型预生成结果。
- 在线静态版可浏览故事、资料库、地图和预生成结果。
- 声音地图已把同坐标的 6 个故事合并为一个节点，点击后下拉选择。
- 已有 GitHub Actions 自动部署和本地 3 分钟演示视频。

### 不要这样讲

- 不要说“已经完成真实 10 人用户测试”。当前只有模拟试玩报告，不能当真实用户证据。
- 不要说“已经采集了外婆 / 长辈真人声音”。当前是浏览器语音合成示例。
- 不要把《阿婆的艇仔粥》说成真实家庭采访，它是待替换的示例故事。
- 不要说声音地图是精准地理数据，它是示意图。
- 不要把“8 个样品通过 7 项检查”扩大成“AI 不会出错”。
- 不要在 GitHub Pages 静态版现场承诺实时生成；实时 `/studio` 需要服务端和模型环境变量。

### 第 1 页｜封面：声迹 VoiceTrace

**屏显文案**

> 声迹 · 方言故事书<br>
> 趁还会唱，把乡音留下来。<br>
> 让方言不只被保存，还能被玩。

页面底部放：在线体验地址、GitHub 地址、作品名 VoiceTrace。

**讲稿**

“大家好，我们的作品叫声迹。它做的事情很具体：把粤语童谣、地方传说和家庭故事，变成一本可以读、可以选、可以听、可以分享的互动书。我们希望保存的不只是方言的发音，还有发音背后的人、地方和生活。”

**画面建议**

首页主视觉，不放复杂数据；标题和一句话占主要画面。

### 第 2 页｜问题：故事还在，但下一代未必接得住

**屏显文案**

- 口述故事缺少低门槛的整理方式
- 长辈会讲，晚辈不一定听得懂
- 地方资料常常“可查阅”，但不够“想参与”
- AI 能生成故事，也可能编造人物、地点和事件

**讲稿**

“很多地方故事并不是没有价值，而是停在了只有少数人听得懂、年轻人又不容易进入的形式里。单纯录音可以解决‘留下来’，却不一定解决‘听懂’和‘愿意继续听’；单纯让 AI 写故事，又会带来事实和来源问题。所以声迹同时处理三件事：参与、理解、可追溯。”

**画面建议**

用“素材 → 理解门槛 → 参与不足”的三段图，不使用未经授权的老人照片或虚构家庭经历。

### 第 3 页｜方案：一条完整的故事体验链路

**屏显文案**

> 素材有据可查 → AI 结构化 → 三幕互动 → 注释与翻译 → 语音示例 → 故事卡与地图

**讲稿**

“声迹不是单独的生成按钮。前面有带来源和授权状态的资料库，中间有三幕、选择、翻译和注释，后面有故事卡和地图。用户可以只打开一个故事体验，也可以继续查看它来自什么素材、AI 输出通过了哪些检查。”

**画面建议**

展示一条六步横向流程；对应页面小截图即可，避免堆代码。

### 第 4 页｜核心体验：把“读故事”变成“走进故事”

**屏显文案**

- 三幕结构与剧情选择
- 方言原文 + 普通话辅助文本
- 点击方言词查看含义和文化背景
- 阅读后生成声音故事卡

**讲稿**

“以《月光光》为例。用户不是从第一行读到最后一行就结束，而是在三幕里做选择。遇到‘地堂’这样的词，可以直接点开，看到它是‘天井、屋前空地’，还能了解它和西关生活场景的关系。语音按钮当前播放的是明确标注的浏览器合成示例。读完后，故事可以生成一张 PNG 分享卡。”

**现场动作**

1. 打开 `/stories/moonlight`。
2. 点击“地堂”注释。
3. 选择一个分支进入下一幕。
4. 展示普通话辅助文本和语音示例标记。
5. 时间允许再展示故事卡，不必现场重复播放整段音频。

### 第 5 页｜内容设计：同一个广州，三种讲法

**屏显文案**

| 模式 | 讲法 | 代表作品 |
|---|---|---|
| 正经 | 温暖、克制、家庭共读 | 《月光光》《老鼠娶亲》《阿婆的艇仔粥》 |
| 鬼故事 | 民俗悬疑，不血腥，结尾有解释 | 《井边的鹰爪兰》《仙湖里的金花》《龙宫煮泉》 |
| 野史 | 说书、俏皮，明确“据传 / 野史” | 《状元及第粥》《陈梦吉的扭计》《珠玑巷的夜》 |

**讲稿**

“只做温情表达，受众容易变窄。因此我们把同一素材库拆成三种叙事语气：给家庭共读的正经模式，给年轻用户的民俗悬疑模式，以及带说书感的野史模式。扩受众不等于放弃边界：鬼故事不血腥、不宣扬迷信；野史不冒充正史。”

**现场动作**

打开 `/stories`，快速扫过三个模式分区；不需要把 9 个故事逐一念完。

### 第 6 页｜内容底座：91 条素材不是一堆无来源文本

**屏显文案**

- 搜索、类型 / 地区 / 模式筛选、详情与导出
- 来源、授权状态、方言词、适用模式、待研究标记

**讲稿**

“AI 的质量先从输入开始。我们已经整理 91 条粤语素材，不是把它们塞进一个大文件，而是按内容子集拆成 23 个分类文件。每条素材尽可能保留来源、授权状态、地区、方言词和适用模式。需要继续研究的内容会明确标记，而不是补写成看似完整的故事。”

**现场动作**

打开 `/library`，演示一次关键词搜索或“鬼故事模式”筛选，再打开一条素材的来源信息。

### 第 7 页｜AI 工程：让“能生成”变成“可验收”

**屏显文案**

> 8 个黄金样品 × 7 项自动检查<br>
> 真实模型：8/8 样品通过 7/7 检查

七项检查：结构、三幕、结局、方言词、翻译、实体依据、前两幕选择。

**讲稿**

“我们没有只用肉眼判断 AI 写得像不像，而是做了 8 个黄金样品。每次生成会检查 7 件事：结构是否有效、是否三幕、第三幕是否收束、指定方言词是否覆盖、翻译是否存在、实体是否有素材依据、前两幕是否有选择。当前真实模型在 8 个样品上都通过了这 7 项检查。这不代表 AI 永远不会错，但代表关键约束可以重复验收，而不是每次靠运气。”

**现场动作**

在线静态版展示 `/demo` 的预生成结果和检查信息；完整服务端可展示 `/studio`，但不要为现场实时等待模型而打断节奏。

## 5. 评委高频问题与回答

### Q1：这和方言翻译器有什么不同？

翻译解决“这句话是什么意思”，声迹解决“我为什么愿意进入这个故事，并把它继续分享”。翻译和注释是理解辅助，三幕选择、三种叙事模式、故事卡和地图才构成完整体验。

### Q2：为什么不直接让大模型生成故事？

因为“能写”不等于“可信任”。我们先做有来源的素材库，再限制实体依据，并用黄金样品检查三幕、结局、方言词、翻译和选择。AI 是生产加速器，不是素材来源的替代品。

### Q3：8/8、7/7 能证明什么？

它证明当前真实模型在既定 8 个样品上通过了我们定义的 7 项结构与 grounding 检查。它不能证明所有开放输入都正确，所以仍需要人工语言润色、事实核查和版权复核。

### Q4：有真实用户数据吗？

目前尚未完成可对外报告的真实 10 人试玩。仓库中的 10 人报告是内部模拟排练，我们不会把它作为真实完成率或用户原话。下一阶段会记录真实完成率、卡点、分享意愿和经同意的反馈截图。

### Q5：是真实长辈声音吗？

不是。当前是浏览器语音合成示例，页面和材料都应明确标注。真人录音需要讲述者授权、隐私保护和删除流程，是下一阶段内容，不作为当前已有成果宣称。

### Q6：《阿婆的艇仔粥》是真实家庭故事吗？

不是，它是用于展示产品形态的示例故事，数据中已经标注“待替换为真实家庭故事”。正式加入真实故事前会取得授权并脱敏。

### Q7：鬼故事和野史会不会不尊重文化或传播谣言？

鬼故事定位为民俗悬疑，不血腥、不低俗、不宣扬迷信，结尾回到故事或民俗解释；野史使用“据传 / 野史”等明确标记，不冒充正史，不攻击真实人物。涉及具体事实仍以公开来源为依据。

### Q8：素材版权怎么处理？

每条素材尽量记录来源和授权状态。传统素材与具体整理版本分开看待，政府或公开网页只提炼事实并改写，参考条目不直接当成可自由使用的正文。正式商用前还需逐条复核。

### Q9：为什么在线 `/studio` 不直接生成？

公开入口是 GitHub Pages 静态演示，没有服务端密钥和 API 路由。静态版用 `/demo` 展示真实模型预生成结果；完整 Next.js 服务端配置模型环境变量后，才开放实时生成。这样既能公开体验，也不暴露 Key。

### Q10：声音地图中的地点准确吗？

当前是故事导航示意图，不是精确地理数据。它已经解决同坐标故事无法选择的问题，后续若要使用真实经纬度，会单独核对地点来源和地图授权。

### Q11：TRAE 具体贡献了什么？

主要贡献包括：需求与信息架构落地、React 组件和页面开发、91 条素材结构化拆分、三种模式提示词和验收逻辑、真实模型问题修复、地图重叠交互改造、移动端验证、静态导出及 GitHub Actions 部署。可展示对应任务记录和关键 diff，而不只展示最终代码。

### Q12：如何商业化？

目前商业化仍是待验证假设，不作为已实现成果。可验证的方向包括家庭定制故事册、学校 / 社区地方文化内容，以及文旅机构的互动故事制作。优先级要由真实用户试玩和机构访谈决定。

### Q13：下一步只做更多故事吗？

不是。优先补真实用户证据、授权家庭故事和人工复核机制。只有确认用户愿意读、愿意完成、愿意分享之后，才扩大素材数量和机构定制能力。

## 7. 现场异常处理

| 情况 | 处理 |
|---|---|
| 在线页面打不开 | 切换本地生产服务；仍不可用则播放本地 MP4，并说明当前演示路径 |
| 模型响应慢或失败 | 不现场重试等待，直接打开 `/demo` 的真实模型预生成结果 |
| 静态版没有实时生成 | 明确解释服务端与静态版边界，展示 `/demo` 和本地完整版 |
| 音频无法播放 | 继续展示方言原文、普通话和注释，说明语音是浏览器合成示例且受浏览器能力影响 |
| 地图操作失误 | 点击外部关闭，再点击合并节点；不要连续快速点击 |
| 时间被压缩 | 保留《月光光》互动、三种模式、8×7 验收和收尾，省略资料库细节与故事卡下载 |
| 被追问未实现功能 | 直接区分“已实现 / 下一步”，不现场编造用户、录音或商业数据 |

## 8. 最后一页可复制的结束语

“声迹现在还是一份早期作品，但它已经跑通了一条完整链路：让素材有来源，让生成有验收，让故事可参与，让阅读可分享。接下来，我们希望用真实用户和经授权的家庭声音验证它。让方言不只被保存，还能被玩；让故事不只被听见，还能继续被讲下去。”
